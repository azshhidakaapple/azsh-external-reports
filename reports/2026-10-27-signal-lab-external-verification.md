# azsh.uk Signal Lab 外部検証レポート

2026年10月27日に実施した外部検証の記録。azsh.uk（ICAT）の公開データのみを用い、本体の Signal Lab とは独立した第二実装で、ベースライン、仮説A／B、5日相対乖離リバーサル、GDELT引け後窓の横断仮説を複製した結果をまとめる。

本レポートは統計的検証の記録であり、投資助言ではない。ここで示す関係は相関の検証であり、因果を主張するものではない。

## 要旨

- ベースラインの判定は独立に再現できた。順張りは Period B で明確に負け、逆張りは Period B で強いが Period A で一貫せず、昇格ゲートは FAIL となった。本体と同じ結論である。
- 数値パリティは未達である。本体のイベント件数と外部の定義候補の件数が大きく異なり、本体の正確なイベント定義が共有されない限り、完全な一致は確認できない。
- 仮説A（低ボラ順張り）と仮説B（過熱スパイク逆張り）は、外部でも本体でも FAIL だった。仮説Aは Period B で反転し、仮説Bは発火がごく少数の営業日に集中して評価不能となった。
- 本体の新本命である5日相対乖離リバーサルは最も近接して複製できた。発火日数・件数とドリフト控除後 AR は同オーダーで再現したが、外部では Period B の信頼区間下限が 0 を割り、昇格可否は未確定である。
- GDELT引け後窓の横断仮説では、トーン条件の付加価値を公開データのどの読みでも再現できなかった。本体のトーン集計の正確な定義が次の突合の鍵になる。
- 公開データ側の発見として、GDELT日次集計系列に2026年7月20日のスキーマ断絶があること、分析マニフェストが Period A 分について未生成であることを確認した。

## 検証の枠組み — 独立した第二実装で同じ方法論を回した

外部ラボは本体の実装とは独立に構築した第二実装であり、本体のコードを流用していない。入力は azsh.uk の公開レイヤーから取得した公開データのみである。

方法論は本体と同一に揃えた。

- セクター固有のドリフトを差し引く Null ドリフト控除
- 日次集約した系列に対する Moving Block Bootstrap による信頼区間の算出
- 昇格ゲート：両期間でドリフト控除後 AR（AR_adj）が同符号であり、かつ信頼区間の10パーセンタイル（CI10）が 0 を上回ること
- 検出力ガード：方向性のある件数（n_directional）が30未満、または発火日が10日未満の場合は INSUFFICIENT_POWER として評価不能とする

検証期間は本体の区分に合わせた。

- Period A：2024年10月29日〜2025年10月24日
- Period B：2025年10月27日〜2026年10月26日

データの来歴は次の通りである。

- ファイル：`sector_baskets_daily.parquet`
- スナップショット SHA-256：`6c3efa690290874f12c69539d0ba76b43bb41e540c27131d2bb0f1f52598d972`（本レポートでは短縮表記 6c3efa69… とも記す）
- 実カバレッジ：2024年9月4日〜2026年10月27日

実カバレッジは、サイトの index.json にある「2025年から」という表記より広く、Period A と Period B の全期間をバスケット経由で検証できた。

出典：ICAT（https://azsh.uk/）の公開バスケットデータおよび公開集計データ。

## ベースライン複製 — 判定は一致したが、件数は一致しなかった

ベースラインは、単日で大きく動いたセクターに対する順張りと逆張りである。外部では、本体のイベント定義が非公開のため、2つの定義候補を併走させた。

- D1：絶対値で2%以上の動きがあった全セクター日
- D2：各日のランク極値にあるセクターで、絶対値で2%以上のもの

### イベント件数の乖離

| 区分 | Period A | Period B |
| --- | ---: | ---: |
| 本体（報告値から逆算した件数） | 29件 | 28件 |
| 外部 D1（全セクター±2%） | 152件 | 292件 |
| 外部 D2（日次ランク極値） | 35件 | 102件 |

D2 の Period A は本体に近いが、Period B ではなお大きな差が残る。セクターリターンの構成方法を含む本体の正確な定義がなければ、この乖離は解消できない。

### 判定の一致

件数が異なっても、方向と判定は再現した。

- 順張りは、両定義とも Period B で明確に負けた。外部の AR_adj は -26〜-27bp で、本体報告の -15.2bp と同方向である。
- 逆張りは Period B で強かった。外部の Null 超過は +11〜+14ポイントで、本体報告の +7.9ポイントと同方向である。
- 逆張りは Period A では一貫せず、昇格ゲートは FAIL となった。これは本体と同じ判定である。
- D2 の Period A における逆張りの超過は外部が -1.4ポイント、本体が -1.2ポイントと近接した。

したがって、ベースラインについては定性的な複製に成功し、数値パリティは未達というのが正確な評価である。

## 仮説A — 低ボラ順張りは Period B で反転した

仮説Aは `jpx17_calm_momentum` で、単日の大きな動きに、ボラティリティが過熱していないという条件（vol_21d_z60 < 1.0）を加えた低ボラ順張りである。過熱局面のオーバーシュートによる反落を避ける狙いがあった。

外部の D1 では、Period A は強かった。

- 勝率 69.8%
- AR_adj +77.1bp
- CI10 +36.8bp

しかし Period B では反転した。

- 勝率 36.6%
- AR_adj -31.1bp

このため、外部の昇格ゲートは FAIL となった。

本体側の結果も同じ方向だった。本体では Stage 1 ゲートが Period A の時点で棄却しており、その理由は条件の追加によって方向性のある件数が11件まで減ったことにある。本体の Period B は勝率 47.6%、AR -8.6bp で FAIL だった。

内外が一致して示すのは、「大人しい日の順張り」も相場の局面に依存し、通年で普遍的な優位性とは言えないということである。

## 仮説B — 見かけの強さは日付クラスタに支えられていた

仮説Bは `jpx17_spike_reversal` で、大きな単日リターン、高いボラティリティ、高い市場ブレドスが重なった過熱スパイクに対する逆張りである。

外部の市場ブレドス解釈では、見かけの数値は非常に強かった。

- 勝率 88.2%
- AR_adj +158.9bp

内訳を確認すると、この結果は評価に耐えなかった。イベントは Period A では2営業日、Period B では5営業日に極端に集中していた。件数ではなく異なる日付で数えた実効標本は、2と5しかない。このため外部では INSUFFICIENT_POWER、すなわち評価不能と判定した。セクター・ブレドス解釈でも Period A は8日どまりだった。

本体側でも仮説Bは FAIL だった。本体報告では Period A の発火は6日、勝率 48.5% で、検出力不足と CI10 が 0 を下回ることが棄却理由に含まれていた。

結論は、日付クラスタの壁である。全面高に近いスパイクの日は2年間でも数えるほどしかなく、この形の仮説は現在の対象期間では統計的に評価できない。

## 5日相対乖離リバーサル — 最も近接した複製、ただしゲートは未確定

本体の新本命は `jpx17_5d_rel_overextension_reversal` である。単日ではなく、5日間でベンチマーク対比 ±2.5%以上乖離したセクターの、5日先までの平均回帰を狙うルールである。

### 外部複製と本体報告の比較

| 項目 | 外部 Period A | 本体 Period A | 外部 Period B | 本体 Period B |
| --- | ---: | ---: | ---: | ---: |
| 発火日数 | 80日 | 72日 | 167日 | 165日 |
| 件数 | 138件 | 119件 | 292件 | 281件 |
| AR_adj | +42.8bp | +32.2bp | +22.6bp | +35.7bp |

発火日数・件数は単日ルールの複製よりも格段に近接し、AR_adj は両期間ともプラスで同オーダーだった。イベント生成の再現性は、このルールで大きく改善している。

### 残る2つの指摘

第一に、外部では Period B の AR の CI10（ブロック長 L=5）が -23.9bp と 0 を割った。外部のゲート基準では FAIL である。本体報告では Period B の CI10 が示されていないため、本体側で同じ基準の CI10 を算出するまで昇格可否は未確定である。

第二に、本体報告の中に Period A の AR について2つの値がある。ある記述では +42.8bp、JSON では +32.2bp である。外部複製は +42.8bp に一致した。パネルの切り方か定義の版が異なる可能性があるため、どちらが正本かを確認する必要がある。

さらに、勝率も Period A で乖離が残った。外部は 50.7%、本体は 57.0% である。この差は、ヒット判定を絶対値の5日先リターンで取るか、ベンチマーク相対で取るかの違いによる可能性がある。これが次のパリティ課題である。

## GDELT引け後窓・横断仮説 — トーン条件の付加価値は再現しなかった

横断仮説は `jpx17_oversold_gdelt_reversal` で、5日間で売られすぎたセクターに、東証引け後の GDELT トーンの底打ちを組み合わせるルールである。

外部では、公開された日次集計 Parquet を取得して引け後窓を構築した。

- 取得できたファイル：421ファイル
- 公開カバレッジ：2025年9月1日から
- 引け後窓：前営業日 07:00 UTC から当日 00:00 UTC まで
- 構築できた窓：279営業日分

公開カバレッジが2025年9月から始まるため、この仮説は Period A を検証できない。外部でも本体の公開データでも、ほぼ Period B のみの単一期間評価になる点に留意が必要である。

### 価格のみの土台

同じ窓で、売られすぎのみを評価した結果は次の通りだった。

- 発火：98日、149件（方向性のある件数）
- 勝率：60.4%
- AR_adj：+69.8bp
- AR の CI10（L=5）：-51.6bp

点推定はプラスだが、CI10 は 0 を下回り、有意とは言えない。

### トーン条件を加えた3つの読み

トーンが -1.0 以上という条件は、母集団の取り方によって全く異なる結果になった。

| 読み | 結果 |
| --- | --- |
| マクロ全件のトーン | 発火ゼロ |
| 日本関連イベントのトーン | AR_adj -6.3bp、効果が消滅 |
| セクター対応タグのトーン | 17件、検出力不足 |

マクロ全件では、引け後トーンの中央値が -1.81 で、-1.0 以上になる日は全体の 0.4% しかなかった。閾値は事実上機能していない。

日本関連では逆に、94.3% の日が該当し、フィルタがほぼ効かなかった。絞った集合は91件で、超過は -2.1ポイント、AR_adj は -6.3bp と、価格のみの結果より悪化した。

セクタータグでは17件しか残らず、検出力不足で、点推定も負寄りだった。

したがって、公開データの3つの読みすべてで、トーン条件の付加価値は再現しなかった。次に必要なのは、本体の `gdelt_overnight_tone` がどの母集団をどう集計した値なのかという正確な定義である。それが共有されれば、同じ定義で第2ラウンドの突合ができる。

## データに関する発見 — スキーマ断絶とマニフェスト未生成が外部検証を制約する

### 公開集計系列のスキーマ断絶（2026年7月20日）

公開された GDELT 日次集計系列には、2026年7月20日にスキーマの断絶がある。

- 2026年7月19日まで：トピック列は `tp`（粗い7分類）、国コードは FIPS 形式で、日本は JA
- 2026年7月20日から：トピック列は `tag1`（10分類）となり、`et` と `is_jp` が追加され、国コードは ISO3 形式で、日本は JPN

断絶を跨いで国フィルタやトピック集計を素朴に結合すると、フィルタが静かに壊れる。本体の内部形式で作成する凍結パネルが無事でも、公開系列を使う外部検証や他の利用者には影響する。凍結パネルを作成する際は、スキーマ版をキーに含めることが望ましい。

### 分析マニフェストの未生成

分析マニフェストについては、Period A 分が未生成の状態だった。そのため、分析層を経由した Period A の完全複製は公開データだけではできない。バスケット経由では全期間を検証できたが、層によって再現可能性が異なることは記録しておく価値がある。

### バスケットの実カバレッジ

前述の通り、セクターバスケットの実ファイルは2024年9月4日からあり、index.json の表記より広い。この差自体は検証を助けたが、表記と実ファイルの不一致は、外部の利用者が検証可能性を誤って低く見積もる原因にもなる。

## 方法論の透明性 — 外部ラボ自身も2件のバグを踏んだ

外部ラボの結果だけを正しいものとして扱わないため、外部側で発生した不具合も記録する。いずれも単体での手計算や診断との突合で捕捉し、修正した上で再評価している。

第一の不具合は、先行5日リターンの rolling の方向を取り違えたことである。最初は有り得ない水準の勝率が出たため、手計算と突き合わせて原因を特定し、修正した。

第二の不具合は、GDELT集計のローダが旧スキーマのファイルを無言で読み飛ばしていたことである。これは、本体側でかつて問題になった「全件スキップによる偽通過」と同じ形の失敗を、外部側で再演したものだった。診断で気づいた後は、読めないファイルがあれば処理を落とす設計に変更した。

この2件は、パネルに格納された値、発火イベントに結合された値、集計結果の3者を突き合わせる検証が、実装の境界を跨ぐ欠落を防ぐ上で有効であることを、外部側でも裏付けている。

## 未解決事項と次のステップ

未解決事項は4点に整理できる。

1. 本体の正確な定義の共有による完全パリティ。対象は、イベント定義（`daily_rank_extreme` とセクターリターンの構成）と、`gdelt_overnight_tone` の母集団と集計方法である。定義が共有されれば、ベースラインと横断仮説の数値パリティを厳密に突合できる。
2. 5日相対乖離リバーサルについて、本体側で Period B の AR の CI10 を算出すること。外部では L=5 で -23.9bp と 0 を割っており、同じ基準で本体値が出るまで昇格可否は確定しない。
3. 本体報告における Period A の AR の2値（+42.8bp と +32.2bp）について、正本を確定すること。外部複製は +42.8bp に一致している。
4. 仮説Bを日単位のイベントへ再定義するか、対象期間を延長すること。現在の形では発火日が少なすぎて、期間を区切った評価が成立しない。

これらが解消されれば、外部ラボは同じ公開データと共有された定義で再評価を行い、結果を本レポートの改訂版として残すことができる。
