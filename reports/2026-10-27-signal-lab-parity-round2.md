## 要旨

第1ラウンドで残っていた最大の未解決事項 — ベースラインの数値パリティ — は、本ラウンドで解消した。

- **ベースラインは完全パリティを達成した。** 本体コードを公開データで実行した結果、本体報告値が小数点以下まで一致した。外部検証の土台（データ・定義・統計エンジン）が本体と同一であることが証明された。
- **外部側の誤認を訂正する。** 第1弾レポートの「本体件数は A=29 / B=28 と推定され乖離」という記述は外部側の誤認であり、併せて「5d ルールの AR の2値はダミーセクター版違いが原因」という外部の仮説も撤回する。
- **5d ルールには残差が残る。** 同一コード・同一公開入力でも本体値と bit 一致せず、発生箇所の特定には本体の凍結パネルと run_manifest の共有が必要である。ただし「Stage 2 FAIL」という結論は内外で一致している。

### 2.3 外部側の訂正 — 第1弾の2件の記述を撤回する

完全パリティの達成に伴い、第1弾レポートの次の2件は外部側の誤りとして訂正する。

1. **「本体件数は A=29 / B=28 と推定され乖離」は誤認だった。** 外部が「28件」と推定した値は実在しなかった。29 は Period A の `n_directional` そのものであり、Period B の勝率 42.9% の分母は 84（36 / 84）だった。外部の定義候補 D2（日次ランク極値）の発火件数（A = 35件 / B = 102件）は、最初から本体と完全一致していた。第1ラウンドで「期間比が決定的に異なる」「ラボのパネルは別構成のはず」とした推論も、この誤認に基づくものであり撤回する。
2. **「5d ルール Period A の AR の2値はダミーセクター版違いが原因」という外部の仮説を撤回する。** 本体回答の通り、+32.2 bp は旧キャッシュによる中間値であり、正本は +42.8 bp である。外部で観測した「ダミー含む / 除外で AR が動く」という事実自体は実測として残るが、それが本体の2値の原因だったという説明は成り立たない。

ヒット判定についても、本体仕様（ベンチマーク相対累積超過リターン AR による判定、閾値 20 bp 未満は判定保留、分母に判定保留を含めない）が共有され、外部の勝率が約6〜7 pt 低かった理由が解明した。外部は絶対リターンの符号で判定していたためであり、定義の差であってデータの差ではなかった。

## 3. 5d ルールは近接するが bit 一致しない

`jpx17_5d_rel_overextension_reversal`（5日間でベンチマーク対比 ±2.5% 以上乖離したセクターの5日平均回帰）については、同一コード・同一公開入力での外部実行結果が、本体正本および本体の先行 JSON のいずれとも一致しなかった。

| --- | ---: | ---: | ---: | ---: | ---: |
| 発火日数 | 70日 | 66日 | 72日 | 171日 | 165日 |
| 件数 | 117件 | — | 119件 | 294件 | 281件 |
| 有効件数 n | 105 | 104 | 107 | 263 | 255 |

| Null 超過 | +11.36 pt | — | +11.0 pt | +2.2 pt | +4.6 pt |
| 超過 CI10 | +3.28 pt | — | +2.8 pt | — | — |
| AR_adj | +34.3 bp | +42.8 bp | +32.2 bp | +14.6 bp | +35.7 bp |
| AR_adj CI10 | +25.5 bp | +21.1 bp | +21.5 bp | −35.7 bp | −3.8 bp |

読み取れることは3点ある。

- **近接はしている。** 勝率と Null 超過は本体値に近く、AR_adj も両期間ともプラスで同オーダーである。第1ラウンドの独立実装が示した方向性は、本体コードの実行でも裏付けられた。
- **しかし bit 一致はしない。** 発火日数、有効件数、AR_adj のいずれも本体の2つの版のどちらとも合わない。ベースラインが同じ条件で完全一致したことと対照的であり、この差は偶然の丸めでは説明できない。
- **ゲートの結論は一致する。** 外部実行では Period A であっても、signed AR の CI10 が −7.3 bp のため Stage 1 は FAIL となった。Period B は CI10 が外部 −35.7 bp、本体 −3.8 bp と水準は異なるが、どちらも 0 を割り、**Stage 2 FAIL（昇格未達）という結論は一致**している。

5d ルールだけがずれる事実は、このルールが複利計算やベンチマーク経路など、小さな入力差に敏感な経路を通るためとみられる。残差の発生箇所を特定するには、本体が評価に使った凍結パネル（`clean_panel.parquet`）そのものと、その `run_manifest`（入力バスケットの SHA-256 を含む）を外部のパネルと突き合わせる必要がある。これが本ラウンドの新たな依頼事項である（第6章 依頼1）。

## 4. GDELT 経路に2件のバグを発見した

`freeze-panel --agg-daily-dir` で結合される GDELT 引け後窓の経路を実測で確認したところ、2件のバグが見つかった。いずれもコードは変更しておらず、所見として報告する。

### バグ G1: `date` がインポートされておらず、実行時に即死する

`signal_lab.py` の `load_gdelt_overnight_windows` は `date.fromisoformat` を使うが、モジュールには `datetime` と `timezone` しかインポートされていない。

- `freeze-panel --agg-daily-dir` を実行すると `NameError` で即死することを実測で確認した
- したがって、GDELT 結合経路は現行 HEAD では一度も完走していない可能性が高い

### バグ G2: セクターキーが一致せず、JPX17 ではトーンが常時 NaN になる

`SECTOR_GDELT_TAGS` のキーは全て英語コード（`BANKS`、`FOODS`、`DEFENSE_SECURITY` 等）だが、JPX17 パネルのセクター名は日本語（銀行、食品 等）であり、両者を結ぶ改名マップは存在しない。

- 実測では、JPX17 の17セクター中マッチは **0件**、FOCUS4 は **4 / 4 マッチ**だった
- 結果として JPX17 行の `gdelt_overnight_tone` は常時 NaN になる
- `threshold_filter` では NaN との比較は常に False になるため、横断仮説 `jpx17_oversold_gdelt_reversal` は**構造的に発火不能**である

加えて、タグ値の多く（`fintech`、`banking_risk`、`central_bank`、`agriculture` 等）は、新旧どちらの agg スキーマのタグ語彙にも存在しない。そのため、キーが一致する FOCUS4 側でも、大半はセクター別トーンが取れずマクロトーンへのフォールバックになる。

この2件により、第1ラウンドで外部が「トーン条件の付加価値は3つの読み全てで再現できなかった」とした結果の解釈も変わる。外部の不発は定義の未共有だけが理由ではなく、本体側でも現行コードでは横断仮説を評価できる状態になかった、というのが実測の結論である。仕様書で共有された窓と集計の定義（前営業日 07:00 UTC 〜 当日 00:00 UTC、トーンは Σtone_sum / Σn、マクロ / 日本関連 / セクター別の3系統）自体は明確であり、修正後の再評価が待たれる。

## 5. 副次所見が2件ある

### 5.1 `parity-test` のカバレッジは薄い

`parity-test` は PARITY TEST 100% MATCH OK を返したが、対象はパネル先頭20営業日の精算2件のみである。パネル格納値、発火イベント結合値、台帳精算値の3者突合という考え方は正しいが、484営業日に対して2件では、境界間のデータ欠落を検知する E2E 突合としてのカバレッジは薄い。対象期間の拡大を推奨する。

### 5.2 `jpx17_narrow_spike_reversal` は両期間とも発火 0 件だった

事前登録ルール `jpx17_narrow_spike_reversal`（低 breadth 急騰の反落、h=2）は、現行パネルでは Period A・B とも発火 0 件だった。仕様上あり得る結果ではあるが、事前登録されたルールが恒常的に不発である点は、ルール棚卸しの材料として共有する。

なお、2026-07-20 の agg スキーマ断絶（`tp` / FIPS `JA` → `tag1` / ISO3 `JPN` / `is_jp`）については、本体ローダー側で両形式を吸収する対応が仕様書とコードで確認できた。この件は第1ラウンドの依頼から解消済みとして扱う。

## 6. 依頼事項（更新）

第1ラウンドの依頼のうち、Signal Lab 一式の push、定義3点への回答、5d ルール Period B の CI10 の開示と Period A の AR の正本確定、スキーマ断絶への対応は解消した。残る依頼は次の3点である。

### 依頼1: 本体の凍結パネルと `run_manifest` を共有する

5d ルールの残差の発生箇所を特定するため、本体が評価に使った `clean_panel.parquet` と、その `run_manifest`（入力バスケットの SHA-256 を含む）を共有してほしい。外部のパネル（10,164 行、全ゲート通過、入力 SHA-256 は本体と同一のはずのもの）と行単位で突き合わせれば、差がパネル生成のどの段階で生じるかを切り分けられる。

### 依頼2: バグ G1 / G2 を修正し、完走を確認する

G1（`date` のインポート漏れ）と G2（セクターキーの不一致、改名マップの欠如）を修正の上、`freeze-panel --agg-daily-dir` が最後まで完走することを確認してほしい。併せて、`SECTOR_GDELT_TAGS` のタグ値が実際の agg スキーマのタグ語彙と一致しているかの点検も推奨する。

### 依頼3: 修正後の横断仮説の再評価結果を共有する

修正後に `jpx17_oversold_gdelt_reversal` を再評価し、その結果を共有してほしい。外部でも同じ条件で再突合し、トーン条件の付加価値があるかどうかを、第1ラウンドで未完だった形で閉じる。
